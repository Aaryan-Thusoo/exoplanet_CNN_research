First, the accuracy explains the model correctly classified about 86.4\% of all the test light curves. Overall this is a strong performance indicating the model can clearly be utilized in further research. On its own however, accuracy is not enough to confirm the model performs equally for both classes. This is why the precision and recall metrics were required. The precision is high while the recall returned a relatively lower result. Thus it is understood that the model does a better job classifying exoplanet transits than it does eclipsing binaries. It is much more common for the network to falsely identify an eclipsing binary as a transit then it is to do the opposite. Next the F1 score works as a balance of the precision and recall. The result in the table depicts a model that maintains a good balance between identifying eclipsing binaries and avoiding false positives, although recall remains the weaker component. Finally, the ROC AUC result is strong and thus the classification threshold of 0.5 separates the two classes well across possible thresholds. There is however still room to try slight variations in the threshold to potentially improve the model further.

\subsection{Binary CNN Confidence and Misclassification Analysis}

Of the \textbf{(How many total?)} test instances used, \textbf{(How many misclassified?)} were misclassified. There were \textbf{(How many false positives?)} and \textbf{(How many false negatives?)} and to understand where the model is making mistakes it is important to analyse the properties of these light curve instances. The first feature to analyse was the distribution of confidence for all test instances. Classifications with low confidence indicate the model was not making an informed prediction and guessed. Misclassified instances with high confidence are the most interesting focus as they tricked the model into being certain of its prediction. Figure~\ref{fig:conf_corr_vs_incorr_hist} shows the confidence distribution of all test instances split by correct and incorrect classifications. With any model, especially in a binary classification model, it is expected to see incorrect instances with low confidence. Thus it is important to analyse the incorrect cases which came back with higher confidences.

To understand where the model is getting high confidence misclassification from, it is helpful to look at features of those light curve instances. The features chosen to be looked into are labelled in Table~\ref{tab:kep_query_cols} and were collected during the query steps in the Methodology. Apart from the \texttt{kepid} label and \texttt{koi\_disposition}, the remaining columns all contain measured features of each light curve used. It is important to note that the calculated SNR developed in the methodology was added to this list for comparison against the \texttt{koi\_model\_snr}. Each of these features are plotted comparing their numbers to the confidence the model returned in its classification. By then looking trends it is possible to look for what features affect the model the most.

The first evaluation is of the signal-to-noise ratios. This is the most important as previous papers work to improve this result before applying any classification models. As the data used in this model has not undergone any heavy filtering, binning, or cleaning steps it is understood the SNR values will be smaller than other papers. To then first compare SNR values, this is done by splitting all instances into a low, medium, and high confidence ranges. All misclassified light curves were then plotted onto Figure~\ref{fig:calc_snr_boxplot} which shows the spread of SNR values for the 3 categories. As the values of SNR scale over large ranges, the y-axis is log-scaled.
